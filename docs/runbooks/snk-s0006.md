# Runbook — `SNK-S0006`, configuration invalid

**Class:** fatal. The process refuses to start.

## Symptom

The server exits at startup with `SNK-S0006`. The detail names the key, the value, and where
the value came from.

## What is actually wrong

A configuration key is unusable — or unknown.

**An unknown key is an error rather than a warning, and that is the part worth explaining.**
A typo in a setting name is one of the leading causes of production incidents, precisely
because the usual behaviour is to ignore it: the operator sets `SANKHYA_WAREHOSE`, the server
starts happily using the default warehouse, and the mistake is discovered when somebody
queries a table that appears not to exist. The server started, so nothing looked wrong.

Refusing to start converts that into a failure at the moment of the change, next to the
change, with the key named.

## What to do

**Read the detail.** It names three things and each one is the answer to a different
question:

- **The key** — what is wrong.
- **The value** — whether it is a typo in the value or the key.
- **The origin** — *where it came from*, which is the one people spend longest guessing. A
  value can arrive from the environment, from a unit file, from a container's environment
  block, or from a default. An operator editing the file while the value is coming from the
  environment will change nothing and see the same error.

**For an unknown key:** check the spelling against the documented settings. If the key is one
that used to exist, it was removed rather than renamed silently — check the upgrade notes for
the version you moved to.

**For an invalid value:** the detail says what was expected.

## What "fixed" looks like

The server starts, and its startup banner shows the setting taking effect. The banner prints
the configuration deliberately, including whether authentication is required, so that a
setting which parsed but did not do what was intended is visible without going to look.

## What not to do

**Do not work around it by removing the key.** If a key was set, somebody wanted its effect.
Removing it makes the server start with the default, which is the silent-typo failure this
error exists to prevent, arrived at deliberately.
