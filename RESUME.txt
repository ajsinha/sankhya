The first build after a reboot is a full rebuild and takes a while. target/
holds ~133 GB of cached artefacts; leave it alone unless the disk is tight.
`cargo xtask check-all` fails the build above 150 GB, and `cargo clean`
reclaims all of it at the cost of that rebuild.

5. THE WORKING RULES THAT STILL APPLY
-------------------------------------
  * Documentation ships in the SAME COMMIT as the code.
  * Every milestone goes through the full git drill:
        verified -> develop -> push -> merge --no-ff into main -> push
        -> develop --ff-only -> push, then check all four refs.
  * `cargo xtask check-all` must be green before merging to main.
  * Nothing is created or deleted outside this project root. Ever.
  * A claim needs a measurement. If a number cannot be re-run, it does not
    get written down.


6. USEFUL COMMANDS
------------------
    cargo xtask check-all            the whole gate (~25 min, needs a quiet box)
    cargo xtask check-fast           the quick subset
    cargo xtask check-loc            file length limits -- counts CODE, not comments
    cargo xtask sync-doc-numbers     fix stale test/mutation counts in the docs
    cargo xtask check-performance    the objectives, against TPC-H
    python3 tools/mutation-audit.py --check      catalogue matches the source
    python3 tools/mutation-audit.py "<label>"    run one mutation
    .venv/bin/python tools/deck/slides.py        rebuild the evidence deck

Python is pinned: .venv, built from 3.13.15 under ~/.local/share/uv/python/.
Rebuild it with `cargo xtask venv` if the virtualenv is missing.


7. TWO BUILD GOTCHAS THAT COST TIME TODAY
-----------------------------------------
  * Adding a module under crates/sankhya-server/src/ is NOT enough. Fourteen
    test binaries include wiring.rs through `#[path]`, and each needs its own
    `#[path = "../src/<new>.rs"] mod <new>;` or they all fail to compile.

  * `check-loc` counts CODE lines, so trimming comments to get under the
    1500-line limit does nothing. Extract functions instead.
